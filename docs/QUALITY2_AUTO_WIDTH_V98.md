## 问题及最小改动

真机前置核验发现：v97切换AUTO会主动重建为旧Canvas/Webtoon；不是当前AUTO已经因WebGPU宽度缺失而必然失效。先前定向审查漏掉ReaderActivity的后端选择边界，主Agent在实际路由断言中发现并纠正，保留失败的探针记录。

本候选让质量模型的AUTO与明确AI超分共同使用现有WebGPU条漫链路，避免智能增强切回旧后端。接入前必须补齐两项缺口：WebGPU未发布AUTO所需的阅读Surface宽度；进程初始宽度为0时，工厂AUTO_WAIT_FOR_WIDTH会被bridge当成不可恢复失败。旧进程残留其他viewer宽度也不能代替当前Surface。新增后端选择回归，保持Pager及API33分页显示滤镜的原有回退。

本候选在活动可见回调启动请求前，将真实Surface物理像素宽度同步到运行态。同宽不失效；仅AUTO下有效宽度变化刷新一次请求代次。派发到viewer Main scope，合并未完成同步，销毁后不回写。零尺寸仍执行原有空视口清理。尺寸未知的AUTO bridge在打开源流前等待，工厂的AUTO_WAIT_FOR_WIDTH也不再永久失败；动画和滚动不因scale变化反复清空请求。

AUTO仍按已有稳定viewport宽度语义决定是否值得运行固定2×网络；不把逐帧pinch scale作为全局请求代次。此修复限定WebGPU条漫集成，不冒称新的逐页投影尺寸算法或新增Pager AI集成。固定“AI超分”模式的输出路径保持不变。已经足够宽的图片仍保留原图，不另叠加退役增强。
