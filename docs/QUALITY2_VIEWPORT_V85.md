# v85候选：条漫底部可见页作为AI当前页

基线：v84 `ea1a2dc1b04f1ced572317938d2e21058ddd1d9c`，ARM64 APK SHA-256 `7238dcf87ec066ec6b0400d93c9d7c2be4abf426a941c415379a84f5397e80da`。继承热时远/近分流；不混入未验收的v83计时读回、新ncnn或模型变更。

用户澄清：条漫可同时显示上、中、下多页，最下方刚进入屏幕的页面应视为AI当前页。阅读进度仍由现有readThrough规则维护，AI调度不能修改滚动位置或把下方刚露出的页直接标为已读。

静态证据：v84连续阅读器的AI head取自`currentPage`，这是滚动顶部锚点；manager给它120优先级，其他可见页100，并从它计算近页窗口。原图`WebGpuDecodeDemand`反序提优先级，生产队列为LIFO，实际也是顶部先解码。AI显示准备按顶部到下部发起。多条短页同时可见时，底部页既排在当前页之后，底部以外真正将读到的近页窗口也被压短。

候选改动：用几何列表最后一项作为AI head（列表已按屏幕自上而下，包含可见占位页）；所有可见页仍保留优先级和缓存保护。原图解码需求与AI输入/显示准备按底部优先安排；空列表回退原锚点，避免初始化阶段无请求。不能按章内最大页码选择底部，跨章索引会重置。

未更改：UI当前页、onViewport/readThrough、进度记录、缩放/裁切、模型/Native、采样/颜色、输出2×、缓存键、严重热保护、推理并发数。原预读推理继续运行，热时priority1远期工作仍让位。未恢复此前未通过收益门槛的额外GPU预热；离屏提前解码/纹理准备是否有净收益仍须独立验证，不能把AI缓存完成写成已提前绘制。

验收范围：主机验证需覆盖三页同时可见/底部仅露一部分/空视口回退/跨章索引/重建。设备验证需保留用户当前留边，分别核查底部原图与AI请求优先级、底部AI_READY到提交、滚动与惯性及热状态。静态逻辑通过不代表底部页首次进入即已AI显示，也不保证阅读速度大于持续推理吞吐时每页完成。

当前为候选。新的设备结果、已跑测试、身份哈希与未执行项在交付记录中单独列明。
