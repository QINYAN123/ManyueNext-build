# v96：可见页优先级整批协调候选

基线：v95 / cb9c1923810912491074f75f1ba6e137d887e16a。权重、Native 二进制、2×输出、显示采样和温控策略保持不变。

## 问题与最小修复

ManyuePrefetchManager 原先遍历请求，逐个调用 updatePriority；每次更新都可能立即抢占 activeRequest。新视口同时包含正在预读的 P 和已排队的 Q 时，如果先遍历到 Q，P 尚未从预读优先级升到可见优先级，Q 就能取消仍在屏幕上的 P。后续给 P 升优先级不能复活取消任务。结果依赖 ConcurrentHashMap 的遍历顺序。

新增确定性生命周期测试选择真实 manager map 中先/后访问的页面，构造 non-predictive active 请求与 queued 请求，再调用真实 onPageChanged。旧实现可重复触发断言失败；独立离屏抢占对照继续通过。它证明该逻辑缺陷存在，不证明它解释了用户遇到的所有慢渲染。

修复：manager 先计算本次视口的完整优先级快照，取消确实不再需要的请求，再在 upscaler 同一个同步区内整批应用优先级、重排队列，最后判断一次抢占。真正离屏的活动预读仍能让出资源，可见页不因其升优先级在遍历中较晚而被取消。

没有删除取消理由、放开无限重试、全面暂停滑动期间 AI 或以缓存状态冒充已绘制。独立单请求提权接口保留原先行为。

## 验证范围

本轮主机先失败/后通过证据、全量测试、APK 身份及安装后阅读结果由配套 verification.json 和设备报告记录。构建成功本身不构成热稳态、功耗或用户手感改善证据。

真机沿用可见区域曝光、Δ=2秒；WebGPU命令提交和呈现请求不等同实际扫描显示。记录既有混合缓存与现场留边，短快滑、正常慢滑、文字停留、小回看及各分辨率案例；不等待所有 AI 预读完成后才起算。正常离屏取消与错误可见取消分别统计。非匹配、逐渐升温和缓存变热的测试不能用于计算性能提升百分比。

## 独立后续问题

- WebGPU AUTO 模式未更新实际阅读区宽度，可能以 AUTO_WAIT_FOR_WIDTH 被永久跳过；需独立复现与修复。
- WebGPU 每个可见周期只允许一次取消重试；二次取消可能等到退出再进入才恢复。应先验证自然触发和修复调度根因，不能直接移除重试限制造成忙循环。
- 源文件暂时不可读与明确超限被合并为终止失败；隐藏页读源失败可能影响回看，需保留永久失败保护并独立验证。
- 超长图的像素/格式预算、跨章首滑、持续自然升温、独立 Surface 帧呈现和输入延迟仍需按本轮结果划分通过与未测。

这些问题没有混入本次最小改动，也不冒充已经解决。密集网点运动伪色不通过全局灰度/模糊牺牲普通彩漫与黑白效果。
