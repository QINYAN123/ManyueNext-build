## 调查顺序

3. 修正中等热状态下远端预读无限等待的问题，改为有限节奏；严重热状态与持续坏帧保护保留。
4. 主机正确性与回归检查、候选 APK/源码及身份验证。

## 首项假设：中等热状态使远端预读无法前进

基线 `ManyueReaderPressurePolicy.reportThermalStatus` 在 Android MODERATE(2) 时永久阻止低于 50 优先级的工作，直到系统降回 LIGHT(1)。当前与最近预读未被 MODERATE 阻止，但长时间文字停留无法用来继续较远的预读。这是代码行为证据，不能替代本轮真机复现。

候选策略：中等热状态不立即封锁，完成一次昂贵 AI 任务后，对较远预读施加该任务耗时四分之一、最长一秒的间隔。当前与最近页面绕过这个温控间隔；严重及以上状态仍暂停新推理。快滑和坏帧规则不变，完成结果的显示不因温控而等待。间隔是候选产品策略，不是温度/能耗的实测最优值，不宣称降温；与旧硬暂停相比会增加中等热状态的预读工作。

预先固定验收范围：主机验证中等热状态下的进展、优先级提升、重复温控回调、降温/退出清理及严重热保护；模型/Native/着色器和缓存像素不变。真机需另补匹配混合缓存的慢读、文字停留、下一章进入、持续热机与实际显示覆盖率、Surface 呈现节奏，未验证前仅为候选。

## 已排除的盲调

原生 2×保留主要计算主干，不能以倍率宣称省算。旧 chunk2、固定小 tile 实验存在回退证据，本轮不重复。保留原模型默认与既有用户数据/留边比例。

## 执行结果

已实现的候选修改：

- 中等热状态：以 Native 任务（含结果提交）耗时的四分之一、最多一秒作为远端预读间隔；当前/最近页优先。等待不会被重复的相同温控回调延长。缓存命中不建立新间隔，退出阅读器/降温后清除间隔。严重及以上状态仍拦截新推理。
- 预读读取原图尺寸：直接对现成 ByteArray 作 bounds-only 解码，不再先复制整份编码图片到 Okio Buffer。仍保留入队工厂独立的尺寸校验，避免混入旋转/切页后的旧元数据。
- 缓存命中：保留一次读取并验证的清单结果，去掉 `getImage -> getBundle -> cachedImage` 后再次读取解析同一清单的调用。缓存 key、清单格式、租约及驱逐规则不变。

定向主机测试通过（温控/运行节奏/缓存行为/PNG、JPEG、无损 WebP 尺寸一致性与输入不变）；完整回归和候选构建的结果见交付目录验证清单。

两个实际 `gpt-6-luna / max` 子 Agent 只读调查，由主 Agent 集成。主 Agent 没有使用工具切换自身模型或推理档位。显示审查排除了常规 WebGPU READY 重复解码/上传与空闲持续重绘；原图纹理保留用于即时回退，释放它会增加回退解码延迟，本轮保留。Canvas 离窗暂存取消属于内存/回看取舍，也不盲目改动。

缓存提交后的自动 trim 的确通常重复扫描，但同身份多预留、有效目标早退和外部/旧缓存超限使其仍有纠偏作用。本轮不删除它；没有为了节省一次扫描而扩大到预算账本迁移。诊断启用时的双摘要也暂不扩张。

本轮不运行设备、不改变系统温控、不调整模型选择、Native、着色器或倍率。不声称已经省电/降温或提高手机帧率；中等热状态放开预读会比旧硬暂停多做工作，收益是可以继续准备后续页，需要真机验证持续表现。

官方语义参考：[Android PowerManager](https://developer.android.com/reference/android/os/PowerManager)：MODERATE 为中度限制、UX 尚未受到显著影响，SEVERE 为 UX 已受到显著影响。具体的四分之一间隔不是官方推荐参数。
