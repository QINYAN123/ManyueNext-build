# 超限长页：全分辨率超分后再缩输出；可选“按阅读区宽度”开关（2026-11-07）

## 1. 超限长页不再整页放弃（默认生效）

固定 2× 质量模型（原模型、原生2×、智能混轴）：2× 输出超过 12MP 的页面（原图超过 3MP，例如 1200×3656 → 2400×7312 = 17.5MP），以前直接拒绝，用户永远只看到原图。

现在**输入保持原图不动**，模型照常做完整 2× 推理，然后由 Native worker 用已有的 `-w` 面积重采样，把结果缩到 12MP 以内的最大宽度。例：1200×3656 → 1984×6045，1200×5000 → 1697×7071。

- 不先缩小原图：用户反馈先缩输入会伤线条，对比实验也证实“先超分再缩”保真度更高。
- 新增 `MAX_NATIVE_INTERMEDIATE_PIXELS = 24MP`：只约束 Native 内部的 2× 中间结果，显示仍以 12MP 为上限。
  - 真机 VER-AN10（Adreno 740）直接运行 APK 内的 worker，峰值 RSS：12MP 中间结果（现有已支持页）384MB，17.5MP 379MB，24MP 377MB。
  - 内存主要来自 GPU 运行时，不随中间图大小增长。
- 缩后宽度必须比原图宽 ≥5%，否则保留原拒绝（例：1000×11000）。
- 真机 worker 输出尺寸与应用的 `targetHeight()` 公式逐像素一致（1984×6045）。

## 2. “按阅读区宽度超分（省电）”开关（默认关）

阅读设置 → 固定 2× 模型下的复选框。开启后，若原图 2× 比阅读区宽 5% 以上，就先把输入缩到阅读区一半宽再超分，省掉屏幕显示不出的像素。

- 实测约快 23.5%（PC 同模型，耗时比 0.765）。
- 代价：12 页许可漫画上 PSNR 每页低 0.3–1.2 dB；文字和线条基本无差别，细密排线放大后稍软。
- 默认关闭，不改变现有画质。
- 切换会使旧任务失效（generation++）。启用时阅读区宽度变化也会重新计算目标。
- 基准测试命令 `displayfit`（enabled=0/1）只改这一项，不像 `configure` 会顺带重置裁边等设置。

## 3. 其他模型评估（真机，同一 worker，4 页 JPEG80 源 → 2090 宽）

| 模型 | 每页耗时 | PSNR | 边缘能量/真值 |
|---|---|---|---|
| 原生2× head3（当前） | 4.86 s | 34.85 | 0.94 |
| 原模型 4×→2× | 5.22 s | 34.90 | 0.95 |
| 双三次（无 AI） | — | 38.04 | 0.92 |

两模型画质几乎相同，head3 快约 7%，保持当前选择。两者都会去 JPEG 噪点、勾清轮廓，但会抹平绘画纹理，因此保真指标低于双三次。

这套 SRVGG 结构的计算量取决于输入像素：1× 纯修复和 2× 超分成本相近，“不固定 2×”本身不省算力。真正提升画质需要更好的模型（例如保留纹理的漫画微调），而训练目前缺少许可明确的独立验证素材。Real-CUGAN 和 Lite 的二进制未打包进 APK。
