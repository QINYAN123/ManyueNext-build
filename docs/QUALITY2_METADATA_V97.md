# v97：将底部可见图的状态与阅读进度分开

继承 v96 / 369065ac291561641c9fae3bc0caa358da5bfb55 的整批优先级修复；不改变模型、Native、采样、温控或阅读进度语义。

## 已核实的问题

连续条漫用 read-through 页维护阅读进度，该页可能已经完全离开屏幕。此前状态栏同时读取这个进度页的 sourceImageInfo，因此可能继续展示旧页的增强/取消状态，无法代表屏幕底部正在看的那张图。

v95 的 color690 记录在约59秒处可核对：状态栏为第17页，实际可见底部为第18页，第17页的曝光已经结束。该采样两页都已就绪，所以它证明归属错位，而不是实际观测到取消文字误显。源码的状态流订阅允许离屏进度页的后续状态继续传到旧状态栏。

## 最小改动

- ReaderViewModel.onPageSelected 及进度保存、当前章节和历史语义保持不变。
- 连续 WebGPU 视口另外发布实际底部页；Activity 仅接受当前 viewer 的回调，旧 viewer 的清理不能覆盖新 viewer。
- Compose 按 sourceImageInfo flow 的身份重建订阅，页码标签切换时不短暂借用旧页状态。
- 状态栏保留原来的进度 N/总页数，明确添加“可见底部第X页”或“相邻章可见底部第X页”，其尺寸和增强状态来自该可见页。
- 连续 WebGPU 暂无可见图片时显示尺寸未知，不借用离屏页的增强状态。其他阅读器维持原来的回退行为。

Formatter 测试使用不同分辨率、进度页取消/加载中与可见页已就绪的组合，检查旧取消说明不能污染可见状态；另覆盖相邻章节与非 WebGPU 回退。正式构建、签名、真机和整体测试结果以对应 verification.json / DEVICE_RESULTS 为准。

这项改动解决状态归属，不能替代推理性能修复或证明热机节能。v96 的真实误取消修复与本项状态归属修复分别保留证据。
